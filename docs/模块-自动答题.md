# 模块:自动答题(做题引擎)

适用版本：v1.0.20（2026-11-17）。项目基础 fork 为 [ZhangYHhhhhhh](https://github.com/ZhangYHhhhhhh/xuexitong-autostudy)，本轮优化参考 [cq-eng](https://github.com/cq-eng/xuexitong-autostudy)，原项目为 [DaRin1403](https://github.com/DaRin1403/xuexitong-autostudy)。完整来源与致谢见 [README](../README.md)。

> 本文把这个脚本里**"做题"**这一整块拆出来单独讲清楚:题目从哪来、答案从哪来、怎么填、什么时候提交、出错了怎么办。
> 对应代码位于 `学习通刷课助手.user.js` 的「答案通道」「题目提取」「测验/作业/弹题」三个段落(脚本内搜索 `/* ====` 分段注释)。

---

## 1. 一句话原理

```
页面题目 DOM ──提取──▶ 题面+选项+题型 ──字体解密──▶ 干净文本
                                              │
                                    ┌─────────┴─────────┐
                                    ▼                   ▼
                             ①大模型通道(主)     ②免费题库站(默认关)
                                    └─────────┬─────────┘
                                              ▼
                                    答案数组 ["A"] ["ABD"] ["正确"]
                                              ▼
                                     清空 → 勾选 → 校验 → 提交
```

一句话:**检查与提取题面 → 需要时解密字体 → AI 作答 → 填写并回读 → 所有已识别题目完成且无漏题才尝试提交**。作答覆盖率不是正确率。

## 2. 题面提取(三种容器都要认识)

学习通不同年份的页面结构不一样,脚本对三种容器分别处理:

| 容器 | 出现的页面 | 识别要点 |
|------|-----------|---------|
| `.TiMu` | 章节测验 / 学习检测(旧版) | 题干取 `.clearfix .fontLabel` 或 `.Zy_TItle`;题型取 `input[name^=answertype]` |
| `.questionLi` | 作业页(doHomeWorkNew) | 保留 `.mark_name` 完整内容,不丢弃第一个 span 中的题干 |
| 弹题 iframe | 视频播放中途弹出的题 | 新版弹窗**没有固定 class**,用启发式**多窗口探测**找题目 |

**选项提取做了三级兜底**(学习通选项 DOM 版本差异大):

1. `ul li .after`
2. `ul li`
3. `.answerBg / .num_option / .after`

此外优先识别 qid/qtype 选项，并支持 ARIA、Element 风格及 option/answer 组件。缺少题型字段时只读本题标题开头的标签及一致的控件结构，不扫描正文关键词，也不借用嵌套子题字段。

v1.0.17 增加两类处理：

- 连线题（11）：解析“第一组数据 / 第二组数据 / 连线答案”和对应原生 select，按第一组编号请求第二组字母。依赖原文的填段落题从当前测验或外层任务 iframe 前方寻找原文，要求空位数与第二组一致；材料不唯一或未读全时跳过。
- 阅读组合题（15）：在已有容器、题型字段、qid/qtype、radio 分组之外，增加按“(1) [单选题]”等连续标题划分的备用方式。范围查询只返回本子题的真实控件，克隆文本仅用于提取，不用于点击。独立题干缺失或选项不足仍按未完成处理。

## 3. 字体加密解密（v1.0.16）

脚本先从当前文档的 CSSOM、内联样式或外链样式表定位匹配的 @font-face，再读取 base64 或 URL 字体。TTF/OTF 的 Unicode cmap 用于筛选字体覆盖的码点；无法解析的字体交由浏览器加载后渲染识字，不能当作普通文字直接放行。

v1.0.15 只检查题面实际声明使用的字体。来源全部为已知标准字体 local(Arial/Times New Roman/宋体等) 时保持原文，不再因为没有 URL 而阻断普通英文题；含远程字体备用来源、未知本地字体、私用码点或 [?] 时仍保留检查。日志显示具体候选字体名、普通字体名和来源类型，便于定位仍失败的页面。

v1.0.16 继续按 unicode-range 与题面字符的交集筛选，避免只用于引号的 CxChineseQuote 阻断整段英文。只有 local() 且范围严格限定为引号的该字体直接保留原文，未知范围或远程来源仍检查。阅读组合题补充 qid/qtype 自定义选项分组，不要求页面存在原生 radio。

v1.0.20 先尝试内置 20,902 条字形指纹，未命中字再采用每批最多 24 格的编号图片和视觉模型，按编号解析 JSON 字符映射。只有全部识别成功才修改原文本节点，并清除相应的加密字体；不重建 innerHTML。失败时保留原题、字体、输入框与事件，停止自动作答并等待检查，不再用 [?] 覆盖原文。

仅带 font-cxsecret 类名但不存在实际字体定义、可疑码点或生效的加密字体声明时，按普通文字读取。字体来源只有 local()、动态 FontFace 或字体文件无法读取时，先通过题目所在文档的 document.fonts.load 确认该字体已经加载，再直接在该文档创建 canvas 渲染识字。不能只靠 fonts.check 判定，以免把系统回退字体当成题面字体。多套自定义字体仍保守跳过该题，记录待检查后继续后续任务。

HTTP 错误、空响应、非 JSON、SSE 流会分别写入日志。真实识字效果取决于字形表覆盖及所配置的视觉模型；本地回归使用合成字体和模拟接口，不代表真实模型或生产指纹覆盖率验证通过。可在设置关闭本地识别并刷新，恢复仅视觉识字；诊断记录两条路径的命中数。详见 [优化说明](fork优化实施与验证.md)。

模型地址现在允许填站点根地址、/v1 或完整 /chat/completions：根地址补全为 /v1/chat/completions，已有自定义路径保留。返回 HTML 时提示检查网关/接口路径。2026-11-17 对 Issues.txt 中配置的接口做过一次成功的四字符图片识别，实际题目仍需核验。

## 4. 答案通道(1.0.6 现状)

阅读组合题先拆分，再将共享材料、该小题题干和选项发送给模型。无法定位子题时不按简答题请求。v1.0.17 已适配具有两组数据与原生下拉框的连线题（11），答案方向固定为第一组→第二组。听力组合题（19）没有音频转写能力时明确跳过。只收到 reasoning_content 而没有最终 content 时不截取思考过程充当答案。

`getAnswers()` 的实际顺序:

| 顺序 | 通道 | 默认 | 说明 |
|------|------|------|------|
| ① | **大模型**(OpenAI 兼容接口) | **需填 Key** | 主通道,准确率最高;未配置时直接跳过并提示 |
| ② | 免费题库站 ×4 | **默认关闭**(`useTiku: false`) | `api.tikuhai.com` / `cx.icodef.com` / `tk.enncy.cn` / `api.muketool.com`,并发查、谁先有结果用谁 |
| — | 都没查到 | — | 记一条 `未查到答案`,该题不填,测验因正确率不达标**不提交** |

**为什么题库站默认关**:这几个站 2025 年起陆续收费/限流,返回的常是"付费/购买/卡密/公众号/扫码"类广告文本。脚本内置 `filterAnswers()` 会把这些词直接过滤掉,但能用 AI 就没必要开它。

> 另有一个**题目收集**功能(独立于查答案):每答完一题就把 题面/选项/答案 存进 `cxQuestions`(上限 5000 条),面板可一键导出 JSON——方便你自建题库或喂给别的工具。

## 5. 大模型通道细节(踩过的坑都在这)

**兼容范围**:任何 OpenAI 格式的 `POST {base}/v1/chat/completions` 都能用——DeepSeek、硅基流动、MiniMax、智谱、通义、Kimi、OpenAI,面板里选供应商 + 点「拉取模型」自动填模型名;也可手填自定义 URL。

**三种题型的提示词**(`buildAIPrompt`):单选要单个字母、多选要字母组合、判断题要 `正确/错误`、填空用 `|` 分隔多空。

**三道保险**(防止推理模型"说一堆话不给答案"):

| # | 保险 | 作用 |
|---|------|------|
| 1 | `system` 消息:"回复的第一个字符必须是最终答案,严禁输出思考过程" | 从对话层面约束 |
| 2 | 用户提示词:"必须以最终答案开头,只输出答案本身" | 再次强调格式 |
| 3 | 最终答案校验 | v1.0.15 起,`content` 留空只返回 `reasoning_content` 时记录失败,不再把思考过程写进答案框 |

**失败处理（v1.0.18）**:

- 默认答题预算 8192 tokens、超时 60 秒,均可在设置修改。自动思考模式仅为 DeepSeek 官方接口发送关闭思考参数,第三方默认不额外传参。
- 截断、仅返回思考、缺失最终答案或答案格式不完整时,最多恢复一次,预算最多翻倍到 32768。思考正文永不作为答案或带入重试。
- 连线题必须返回完整数量和合法字母;任何截断内容即使看似完整也不能填写。
- 同一题首轮与恢复都失败才计一次失败;连续三题失败后进入 **10 分钟冷却**,冷却期内其他题仍走已启用的题库通道。
- 日志记录 finish_reason、最终答案/思考长度及 token 用量;题目导出增加 aiDiagnostics。HTTP 401、网络/超时、拒绝/过滤不触发内容恢复。
- **常见根因:代理**。如果是全局模式的梯子,`api.deepseek.com` 会被代理劫持(表现为 `HTTP 000`),请退出代理或把 API 域名加入直连规则。

**答案解析**(`parseAIAnswer`):

| 题型 | 解析规则 |
|------|---------|
| 单选 | 整段仅接受一个 A–H 字母，并检查实际选项范围 |
| 多选 | 整段字母组合或分隔的 A–H，去重并检查实际范围 |
| 判断 | 整段为明确肯定/否定词；解释或不确定结果拒绝，不默认当作错误 |
| 填空 | 按 `|` 切分,去掉空项 |
| 连线 | 按分隔符读取字母,校验答案数量等于第一组数量,且字母存在于第二组 |

## 6. 填选与提交

v1.0.14：关闭自动提交、题干遗漏、填选回读失败或解密失败时，尝试暂存并继续后续任务、标签页和章节，不再自动暂停，也不把暂存当作平台完成。自动遍历结束后日志统一列出待检查的章节标识和任务名。清单按课程保存在当前浏览器标签页的 sessionStorage 中，跨页加载可保留，后续检测到任务点完成时移除对应记录。暂存调用成功不等于服务器确认保存；找不到接口或调用失败会明确提示，仍按用户要求继续。

- **设置目标状态**：勾选目标、取消多选残留，每次点击后回读，已选中的不重复切换。
- **选项适配**：qid/qtype 优先；语义组件按唯一精确文本定位并去重。原生 checked 或显式 aria-checked 状态优先，新组件的普通 active/focused 变化不能视为成功。
- **提交策略**：漏提取、未填写或回读失败都会阻止提交；全部通过后才应用自动提交开关与覆盖率条件，否则尝试暂存。

## 7. 节奏配置(1.0.5「极速模式」起默认全 0)

| 配置项 | 默认 | 作用 |
|--------|------|------|
| `answerIntervalMin/Max` | `0 / 0` | 每题之间等待秒数,0 = 立即下一题 |
| `submitDelayMin/Max` | `0 / 0` | 提交前等待秒数 |
| `quizDelayMin/Max` | `0 / 0` | 弹题作答前等待秒数 |
| `deliberateErrorRate` | `0` | 故意答错率(旧版 8%),0 = 不故意错 |
| `minAccuracy` | `0.6` | 历史覆盖率阈值；当前还要求无漏题、全部填写且回读通过 |
| `speed` | `2` | 视频倍速(上限 2) |
| `dailyLimitMinutes` | `0` | 每日刷课时长上限,0 = 不限 |
| `useTiku` | `false` | 免费题库站开关 |
| `aiEnabled` / `aiKey` / `aiUrl` / `aiModel` | `false` / 空 / DeepSeek / `deepseek-chat` | 大模型通道 |

> 想换成"保守模式"就自己把间隔、答错率、倍速调回拟人化数值——**但请理解**:拟人化只能降低统计特征上的异常,不能"隐藏"自动化行为,风险始终由使用者承担。

## 8. 排错速查

| 现象 | 原因 / 处理 |
|------|------------|
| 日志 `⚠ 未启用 AI 答题` | 面板 ⚙ 勾选「AI 答题」并填 Key |
| `AI 请求失败: HTTP 000` | 代理劫持,退出梯子或配置直连 |
| `HTTP 401 / 402` | Key 错误 / 余额不足 |
| `返回内容为空`、`解析失败` | 换模型(如 `deepseek-chat`)或检查提示词兼容性 |
| `未查到答案` 且无 AI 报错 | 题库通道已关且 AI 未启用,属正常 |
| 题目文字是乱码 | 字体解密失败,看日志里 `还原 N/M` 比例 |
| 完全不动、没有做题日志 | 页面结构不在这三种容器内(新页面),需要加提取规则 |
| 填了但没提交 | 正确率低于 `minAccuracy`,自己核对后手动提交 |

## 9. 想自己扩展

- **加一个题库来源**:在「答案通道」段复制 `channelTikuHai` 的写法(用 `cxFetch` 发请求、`onload` 里 `done(答案数组, 错误信息)`),再加进 `getAnswers` 的 `Promise.all` 列表;
- **换模型/自建中转**:面板选「自定义」,填 `https://你的域名/v1/chat/completions`;
- **加题型**:`buildAIPrompt` 加一个 `case`,同时补 `parseAIAnswer` 的解析分支即可。
